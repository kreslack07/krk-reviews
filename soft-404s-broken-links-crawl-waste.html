Soft 404s and Broken Links: The Crawl Waste Small Sites Never Audit

Published 2026-11-22 · By KRK Digital Products (ABN 71 770 320 895, Australia)

Two different failures, one report

A 404 is an honest answer: the URL does not exist and the server says so. A soft 404 is a lie with good manners — the page returns HTTP 200 and then shows a "not found" message. Google's definition is exactly that: a page that "returns a user-friendly 'not found' message but not a 404 HTTP response code".

Both land in the same Search Console report. Open Page indexing and the counts sit apart: Not found (404) and Soft 404, beside Crawled — currently not indexed and Discovered — currently not indexed.

What Google does with each one

Google's crawler documentation is specific: on a 2xx status, if the content suggests an error — an empty page or an error message — Search Console reports a soft 404. On 404 (not found) and 410 (gone), the indexing pipeline removes the URL from the index if it was previously indexed, newly encountered 404 pages are not processed, and crawling frequency gradually decreases.

Redirects are not free either: Google's crawlers follow up to 10 redirect hops by default, and the Inspection Tools do not follow redirects at all — so a chain can look like a dead end in one tool and work fine in a browser.

Why the soft 404 is the expensive one

A real 404 costs you one crawl and closes the loop. A soft 404 stays open indefinitely: the URL keeps returning success, so it can never be consolidated or redirected cleanly, it keeps earning impressions for a page with nothing to give, and the visitor gets an apology and a dead end. The usual sources are templates, not typos: a store search with no results, a deleted product the CMS still serves, an empty category page.

Finding them in twenty minutes

  1. Read the report. Filter Page indexing by 404, then by Soft 404, and export the example URLs.
  2. Ask your own 404 handler. Request a URL that cannot exist and read the status code: curl -s -o /dev/null -w "%{http_code}\n" https://example.com/this-page-cannot-exist-9182. If that prints 200, every not-found page on the site is a soft 404.
  3. Count the hops. curl -sIL -o /dev/null -w "%{num_redirects} %{url_effective}\n" https://example.com/old-url shows how many redirects a visitor takes and where they finish.
  4. Check your own links first. Google's guidance is to fix only the 404s you link to yourself or list in a sitemap, and to return a 3XX redirect when a page has moved.

The fix order that saves the most

  1. Broken internal links and sitemap entries you control: repoint them at the live equivalent.
  2. Moved pages: a single 301 to the closest live page. One hop, no chains.
  3. Deleted with no replacement: return 404 or 410, not a 200 apology.
  4. Your 404 template: make it return a genuine 404 and give the visitor a way forward.
  5. Re-export after four weeks so you watch the count fall instead of guessing.

What a self-check cannot tell you

Search Console lists example URLs only and caps the list, so a clean-looking report is not proof of a clean site. A full crawl of every internal link, a redirect map with a replacement URL for each hop, and a fix order ranked by traffic is the part most owners never get to.
