Sitemap lastmod and priority: what Google actually uses

Published 2026-11-24 · By KRK Digital Products (ABN 71 770 320 895, Australia)

Most small-business sitemaps get edited for the wrong thing. The two tags owners spend the most time tuning are the two Google states plainly that it ignores — and the tag that genuinely can influence crawling is usually the one nobody checks.

Google ignores priority and changefreq

Google's sitemap documentation is blunt: “Google ignores <priority> and <changefreq> values.” The sitemaps.org protocol treats both as optional hints — it says changing priority is “not likely to influence the position of your URLs in a search engine's result pages”, and that a crawler may fetch a page marked “yearly” more often than that, or a page marked “never” anyway.

If a monthly job re-tunes priority numbers on your sitemap, that is time spent on a field with no measured effect on Google. Delete the ritual.

lastmod is the tag that can count

“Google uses the <lastmod> value if it's consistently and verifiably (for example by comparing to the last modification of the page) accurate,” the docs say. The protocol adds the rule that breaks most sites: the date “must be set to the date the linked page was last modified, not when the sitemap is generated.”

The usual failure is a CMS that regenerates the file nightly and stamps every URL with that day's date. Once Google sees lastmod values that do not match what it finds on the page, the signal is discounted across the file. Test three URLs: compare the sitemap date with the page's own “last updated” line, and with the server's Last-Modified response header. If all three disagree, the tag is noise.

What actually gets enforced

  • A single sitemap file: no more than 50,000 URLs and no larger than 50 MB (52,428,800 bytes) uncompressed. Gzip is allowed, but only if the file is inside the limit once uncompressed; otherwise split it and submit a sitemap index.
  • The file must be UTF-8 encoded, contain absolute URLs, and list URLs from one host. Google will attempt to crawl each URL exactly as written, so a typo is a wasted request.
  • List only canonical URLs you want in results — not duplicates, redirects, noindex pages or 404s.

Location and submission

Google recommends posting the sitemap at the site root, because unless it is submitted through Search Console a sitemap “affects only descendants of the parent directory”. Reference it in robots.txt (Sitemap: https://example.com/sitemap.xml) and submit it in Search Console, where you can also read fetch errors. Submitting is “merely a hint: it doesn't guarantee that Google will” crawl or index anything.

The 15-minute monthly check

  1. Does every <loc> return a 200 and is it the canonical version of the page?
  2. Do lastmod values match reality on a sample of five pages?
  3. Is any redirect, noindex page, duplicate or 404 still listed?
  4. Is the file UTF-8, under both limits, and one host?
  5. Is it at the root, in robots.txt, and submitted in Search Console?
