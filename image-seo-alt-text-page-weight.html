Image SEO for Small Business Sites: Alt Text, Filenames and Page Weight

Published 2026-11-21 · By KRK Digital Products (ABN 71 770 320 895, Australia)

Google's image best practices are short and specific, and most small sites fail them for unglamorous reasons: the picture is a CSS background, the filename is IMG_2841.jpg, the alt attribute is empty, and the file is a 3 MB JPEG straight off a phone.

That is not cosmetic. Images are usually the largest contributor to page size, and a phone on 4G feels every megabyte before it reads a word of the copy.

First, Google has to find the image

  • Use real <img> elements. Google reads the src attribute, including inside a <picture>; images set in CSS are not indexed.
  • Supported formats: BMP, GIF, JPEG, PNG, WebP, SVG and AVIF — and the extension should match the actual file type.
  • Responsive markup still needs a fallback: give srcset and <picture> a plain src attribute as well.
  • An image sitemap can declare images hosted on another domain, so a CDN is fine.

Alt text is the attribute that carries weight

Google calls alt text the most important metadata for an image. It is read alongside computer vision and the surrounding page text to work out what a picture shows, it is what a screen-reader user hears, and when an image links somewhere the alt text is used as the anchor text — so it should describe the destination, not the picture.

Google's own example: alt="puppy" beats a missing attribute, alt="Dalmatian puppy playing fetch" beats both, and a stuffed string of breeds and phrases drifts toward being treated as spam.

Filenames and captions

Renaming IMG00023.JPG to my-new-black-kitten.jpg gives Google a light clue and costs nothing. The guidance is explicit that generic names such as image1.jpg or pic.gif should be avoided, and that images are interpreted in the context of nearby text and captions.

Weight is the part customers feel

The same page states that images are often the largest contributor to overall page size, and points at image optimisation and responsive-image techniques. In practice: resize to the largest size actually displayed, export WebP or AVIF, set width and height so the layout does not jump, and lazy-load what sits below the fold. Then measure with PageSpeed Insights. On a typical small business site one unoptimised hero image decides Largest Contentful Paint on its own.

One image, one URL

Google asks that the same image be referenced with the same URL across a site, so it can cache and reuse the file instead of requesting it again. Serving logo_v2.png, logo-final.png and images/logo.png from different templates wastes crawl effort for no benefit.

What to do this week

  1. Open the home page and one service page and list every image with a missing or empty alt attribute.
  2. Rewrite those alt attributes as a description of what the image shows, in the language of the page.
  3. Rename the worst filenames and update the references.
  4. Re-export one hero image at 1600 px wide as WebP and compare the file size.
  5. Re-run PageSpeed Insights and watch page weight and Largest Contentful Paint.
