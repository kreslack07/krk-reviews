Discovered vs Crawled – Currently Not Indexed: What Each Search Console Status Means

Published 2026-11-24 · By KRK Digital Products (ABN 71 770 320 895, Australia)

Two Search Console statuses sound almost identical and mean opposite things. One says Google has not fetched your page yet; the other says it fetched the page, read it, and decided not to put it in the index. The fix for each is different, so the first job is telling them apart.

Discovered – currently not indexed

Google's definition: “The page was found by Google, but not crawled yet. Typically, Google wanted to crawl the URL but this was expected to overload the site; therefore Google rescheduled the crawl.” The report shows an empty last-crawl date, which is the tell.

Nothing here says the page is bad — Google knows the URL and has postponed the fetch. It also means a “request indexing” click is competing with a backlog, so the useful moves are the ones that reduce that backlog:

  • Confirm the URL is linked from a page Google has already indexed, not only from the sitemap.
  • Check server response time and whether the host returns intermittent 5xx errors; a slow or unstable server is the classic cause of rescheduled crawls.
  • Make sure a robots.txt rule is not accidentally blocking the URL or the directory.

Crawled – currently not indexed

Google's definition: “The page was crawled by Google but not indexed. Google doesn't index all pages across the web, so this is a common message for many sites and doesn't necessarily indicate an issue that needs attention.”

In practice the page failed a value test against what is already indexed. The usual causes: two pages selling the same service with near-identical copy; category or tag pages that are mostly boilerplate plus a list; filter, sort and pagination variants; or a page that answers nothing a buyer searches for.

The fixes that move it are editorial, not technical — merge the near-duplicates and keep one strong URL, add the specifics that are missing (the service, the suburb, the price, the actual answer), and link the page from an indexed page. If a URL exists only for navigation, leave it out of the index and let the canonical page carry the topic. Google is clear that a duplicate or alternate page not being indexed “is usually a good thing”.

Where to look, and what to expect

Use the URL Inspection tool for one URL — it reports the index status, the crawl date and the Google-selected canonical. Use the Page indexing report for site-wide patterns. Google's own guidance for small sites is that if your site has fewer than 500 pages you “probably don't need to use this report” first; run site:yourdomain.com and site: plus the exact URL to check whether the page is indexed at all.

Watch for the third status hiding in the same table: “Duplicate, Google chose different canonical than user” — Google indexed a different URL than the one you nominated. That is a canonical signal problem (internal links, rel=canonical, redirects), not a content problem.

Once you fix and validate, expect patience: validation “typically takes up to about two weeks, but in some cases can take much longer”. Google's own shortcut is to build a sitemap containing only the pages that matter and filter the report by that sitemap before validating — a smaller set completes faster.
