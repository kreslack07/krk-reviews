URL Structure for Small Business Sites: The Rules Google Actually Documents

Published 2026-11-27 · By KRK Digital Products (ABN 71 770 320 895, Australia)

URL structure attracts more folklore than almost any other part of SEO. Keywords in the domain, folder names, word counts, “SEO-friendly” permalink plugins — most advice on it is recycled. Google publishes an actual specification for this, and it is short enough to read in full. Here is what it says, split into requirements, recommendations, and things you can stop worrying about.

The hard requirements

Google's URL structure best practices page opens by stating that a site which fails these will likely be crawled inefficiently, “including but not limited to extremely high crawl rates, or not at all”:

  • Follow IETF STD 66. Characters the standard defines as reserved must be percent encoded.
  • Do not use URL fragments to change content. Google states it generally does not support URL fragments, so a URL like https://example.com/#/potatoes is not a page. If you are changing content with JavaScript, use the History API instead.
  • Encode parameters consistently. Use = between key and value and & for additional parameters, with a comma for multiple values of the same key.

The documented best practices

  • Use descriptive words, not ID numbers. Readable words beat index.php?topic=42&area=3a5ebc944f41daa6f849f730f1.
  • Use hyphens, not underscores. Google explains the reasoning: underscores commonly denote concepts that stay together, as in programming function names, while hyphens clearly signal a word boundary.
  • Use your audience's language in the URL, transliterated where needed.
  • Percent encode non-ASCII characters in your links' href attributes.
  • Use as few parameters as you can — trim any that do not change the content.
  • Remember URLs are case sensitive. Google treats /APPLE and /apple as distinct URLs. If your server treats them the same, standardise the casing.
  • For multi-regional sites, use locale-specific URLs such as a country subdirectory.

Directories group topics — and affect crawl frequency

The Starter Guide notes that grouping topically similar pages in directories helps Google learn how often URLs in each directory change. A rarely edited /policies/ folder and a frequently updated /promotions/ folder can then be crawled at different frequencies.

What matters less than people think

The Starter Guide is explicit that keywords in your domain name or URL path have “hardly any effect beyond appearing in breadcrumbs”, and that the TLD only matters for country targeting and is usually low impact. It also says the keywords meta tag is not used by Google Search at all.

If you must change a URL

Change as few as possible, and where you do, map every old URL to its new one permanently so the signals transfer. Where problem URLs are being crawled repeatedly — search results, filter combinations, calendars, session IDs — Google's guidance is to block Googlebot from them with robots.txt rather than let them consume crawl budget.
