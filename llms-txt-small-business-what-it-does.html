llms.txt: What It Is, What It Doesn't Do, and Whether Your Small Site Needs One

Published 2026-11-22 · By KRK Digital Products (ABN 71 770 320 895, Australia)

What the file actually is

/llms.txt is a markdown file a site can publish so an AI agent can find the pages worth reading without parsing the whole website first. The proposal was written in 2024 and now stands at v2, revised after two years of adoption. It is deliberately boring: markdown, no schema, no JavaScript.

The v2 spec fixes the order of the file — an optional byte-order mark, an H1 with the name of the project or site, a blockquote summary, zero or more plain markdown sections holding the detail, then H2 sections of link lists. The H1 is the only required part. The file can live at the site root or at any path, and covers the URLs beneath it, so an agent should use the most specific file that applies.

Why an agent wants one

Web pages are built for people: navigation, ads and JavaScript wrapped around the information, and converting that back into clean text is difficult and imprecise. Context windows are large but still too small for most sites in full, and every wasted token costs time and money. The file stays small enough to fit in context, and the detail lives behind its links, fetched only when needed.

What it does not do

  • It is a proposal, not an enforced standard. Nothing obliges a crawler to fetch it, and no search engine has to honour it.
  • It is not access control. Who may crawl a URL is decided by robots.txt rules, noindex and HTTP status codes.
  • It is not a ranking or citation switch. It makes your site cheap to read, not worth reading.
  • It will not rescue an unreachable page. If a crawler cannot fetch it, a line in a text file changes nothing.

The markdown-twin half most sites skip

v2 also proposes a clean markdown version of each page at the same URL with the extension replaced — page.html.md or page.md — linked with rel="alternate" type="text/markdown" and described by rel="describedby". Either can be sent as a <link> element or as an HTTP Link: response header, so your server or CDN can do it without editing a page.

Who is actually reading it

Adoption is heaviest in software documentation, where coding agents follow the file to find API references — the case it was written for. Thousands of sites publish one, documentation platforms generate them automatically, and Chrome's Lighthouse audits for one as part of its agentic-browsing checks. OpenAI, Anthropic and Google publish their own for their developer documentation.

The ten-minute version for a small site

  1. List the ten to twenty pages you would want quoted: services, pricing, and the questions you answer every week.
  2. Write the H1, one blockquote saying what the business does and where it operates, then group the links under two or three H2s.
  3. Keep it short. Detail belongs behind the links.
  4. Generate it from the same list as your sitemap so the two cannot disagree. This site's is at /llms.txt.
  5. Then do the part that pays: the pages have to be crawlable, fast, text-first and specific.
