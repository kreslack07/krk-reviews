Noindex, robots.txt or Removal: How to Actually Get a Page Out of Google

Published 2026-11-22 · By KRK Digital Products (ABN 71 770 320 895, Australia)

Three tools, three different jobs

Most small-business owners who want a page gone from Google reach for the same tool: they open robots.txt and add a Disallow line. Google's own documentation is blunt about why that backfires. A robots.txt file "tells search engine crawlers which URLs the crawler can access on your site" and is "used mainly to avoid overloading your site with requests; it is not a mechanism for keeping a web page out of Google."

The tool that actually removes a page from Search results is noindex — a rule you set with a <meta> tag or an HTTP response header. Each one has a different job, and mixing them up is the single most common technical SEO mistake I see on small sites.

What robots.txt really does to a page you want gone

  • The URL can still appear in Google Search results, it just won't have a description.
  • A disallowed page "can still be indexed if linked to from other sites" — Google may find the URL elsewhere, and the anchor text pointing at it can show up too.
  • Blocking the URL also blocks the fix. Googlebot reads robots.txt before it fetches the page, so it never sees a noindex tag you added to a blocked page.
  • Blocking a JavaScript or CSS file the page needs can stop Google understanding the page at all.

So robots.txt is a crawl-traffic tool. It is not a visibility switch.

The correct sequence for a thin or duplicate page

  1. Remove the robots.txt block on that URL. This is Google's explicit instruction: "remove the robots.txt block and use 'noindex'".
  2. Add the noindex rule — <meta name="robots" content="noindex"> in the <head>, or an X-Robots-Tag: noindex response header, which is the only option that works for PDFs, images and video files.
  3. Ask for a recrawl with the URL Inspection tool. Google has to crawl the page to see the rule, and "depending on the importance of the page… it may take months for Googlebot to revisit".
  4. Watch the Page Indexing report, which lists the pages on your site from which Googlebot extracted a noindex rule.
  5. Choose the right end state: 404 or 410 if the page is gone for good with no replacement, a canonical to a surviving page if it is a duplicate, noindex if the page must stay live for logged-in users or campaign traffic.

When the page has to be gone today

A noindex rule is a request that waits for the next crawl. If the content is urgent — a leaked price list, a staff name you shouldn't have published — Google's Removals tool is the fast path, and noindex is what keeps it gone afterwards. If the content is genuinely private, password-protect it instead; a page behind a login is not crawled, indexed or searchable.

The five-minute check on your own site

Run curl -I against the URL and look for an X-Robots-Tag header. Open the URL Inspection tool and read the HTML Googlebot actually received, which is the only version that counts. Fetch your robots.txt and confirm the URL isn't caught by a wildcard you forgot. If the page is still in Search results, that sequence tells you which of the three tools is the reason.

Getting this wrong is quiet: the page keeps earning impressions and burning clicks on a result that can never satisfy the searcher.
